# Explicit private stage paths

The launcher supports portable **archived-input reruns** and standalone upstream builders. It is not a completed raw-to-all-extensions orchestrator. A `check` prints its exact scope; it never means that the whole stage was executed.

Keep the JSON configuration outside the release. All input roles and historical mapping destinations must lie inside explicit `read_roots`. Output directories must be new, outside every input/archive/source root; only base `--resume` and `donors-finalize` accept an existing private output. No source tree or original freeze is copied, overwritten or regenerated by the launcher.

## Configuration

`roles` maps the following names to local paths. Use absolute paths on your own machine; none are distributed here.

| Role | Read-only input |
|---|---|
| `reference` | Private `paper/reference` directory, including etri/external/displays |
| `raw`, `data` | Authorized raw ETRI root and data root |
| `external_inputs` | Private JSON containing `external_project` for the base runner |
| `base_inputs` | Original base reproduction directory with validation and pinned vendors |
| `base_fresh` | Completed base stage root containing prepare/g2/stress |
| `m0`, `legacy_results` | Complete M0 preflight and legacy recovery directories |
| `same_day_results`, `donor_inputs` | Same-day results and trusted donor inventory |
| `same_day_protocol`, `cross_day_protocol`, `prediction_protocol` | Original immutable FROZEN_PROTOCOL.json files |
| `external_provider` | Root containing StudentLife, ExtraSensory.per_uuid_features_labels and 02_experiments |
| `external_inventory_inputs` | Original prepared windows and source_manifest.json |
| `external_windows` (optional) | Deduplicated windows directory; defaults to external_inventory_inputs |

The launcher assigns `work_output`; do not set it manually. `mappings` is a list of `{"from": "<historical-root>", "to": "<current-private-root>"}`. Matching uses the longest whole-directory prefix; traversal and unmapped historical paths fail. `source_roots` maps `{"code": "<release/extensions>", "original": "<original-extension-root>"}` and similarly for `original_paper_reproduction`. Original frozen source hashes and reviewed packaged hashes are checked separately. This never returns a fabricated hash for changed code.

```json
{
  "roles": {},
  "read_roots": ["<authorized-archive>", "<release-root>", "<private-external-roots.json>"],
  "mappings": [],
  "source_roots": []
}
```

Fill all roles needed by the chosen stage. The skeletal example intentionally contains no participant identifiers or machine-specific paths.

## Commands

Run from the release directory with the pinned environment activated. All outputs below are private: stage runners can write participant-level derived records. They must not be published.

```text
python -B scripts/portable_run.py check base --config "<private-paths.json>"
python -B scripts/portable_run.py check same-day --config "<private-paths.json>"
python -B scripts/portable_run.py check cross-day --config "<private-paths.json>"
python -B scripts/portable_run.py check donors --config "<private-paths.json>"
python -B scripts/portable_run.py check prediction --config "<private-paths.json>"
python -B scripts/portable_run.py check external-inventory --config "<private-paths.json>"

python -B scripts/portable_run.py run m0 --config "<private-paths.json>" --output "<private-runs>/m0-small" --limit 1
python -B scripts/portable_run.py run same-day --config "<private-paths.json>" --output "<private-runs>/same-small" --limit 1
python -B scripts/portable_run.py run cross-day --config "<private-paths.json>" --output "<private-runs>/cross-small" --limit 1
python -B scripts/portable_run.py run canonicalize --config "<private-paths.json>" --output "<private-runs>/canonicalized"
```

After generating M0, a separate private configuration can point `m0` at that new output and include it in `read_roots`. `run legacy --config ... --output ...` consumes it. The one-cell M0 -> legacy chain was actually tested. Reusing original M0 uses a distinct source-provenance gate.

Long stages are explicit commands, not run automatically by `check`:

```text
python -B scripts/portable_run.py run base --config "<private-paths.json>" --output "<private-runs>/base-full"
python -B scripts/portable_run.py run donors --config "<private-paths.json>" --output "<private-runs>/donors-full"
python -B scripts/portable_run.py run donors-finalize --config "<private-paths.json>" --output "<private-runs>/donors-full"
python -B scripts/portable_run.py run external-inventory --config "<private-paths.json>" --output "<private-runs>/external-inputs"
python -B scripts/portable_run.py run verify-external --config "<private-paths.json>" --output "<private-runs>/external-check"
python -B scripts/portable_run.py run prediction --config "<private-paths.json>" --output "<private-runs>/prediction-full"
```

These full commands were not executed in this preparation. `donors` selects `build_inventory_serial_partial.py`: despite its historical name, it loops over all 50 partitions from an empty output. `build_inventory.py` is retained as provenance for historical parallel continuation and is not the default fresh route. `verify_inventory_attempt01.py` is excluded as a superseded failed-attempt verifier.

## Separate bounded fresh route

Do **not** treat the portable commands above as one validated full raw-to-paper chain. Their default route retains original M0/legacy hashes and the full frozen donor tree. Pointing those archived routes directly at arbitrary new manifests still fails at the historical gates.

The new `scripts/fresh_chain.py` route in `FRESH_CHAIN.md` explicitly separates original historical provenance from fresh consumed parents. It verifies both, preserving original frozen bytes. It supports at most five recovery cells, all 50 draws, full-population selection/scales and complete within-participant donor dates. Each new stage and the active configuration are independently hash-bound. This does not authorize or validate a full-study execution. Never change original protocol hashes or invoke a new freeze to connect stages.

External canonicalization is different: the new 6,211-window output was byte-identical to the existing prediction protocol's window hash. A private mapping may point that historical window path to this new file, and the unchanged exact hash gate still applies. This is regeneration from archived prepared windows, not from provider files.

Private references for base commands/tests can also be supplied through `ICTC_PRIVATE_REFERENCE`. Optional fixture roots use `ICTC_TEST_ROOTS`; the original synthetic downstream fixture uses `FULL_DOWNSTREAM_ORIGINAL_TEST_ROOT`. No local root file belongs in the public tree.
